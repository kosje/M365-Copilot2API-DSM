### v1.6.35 — 修复客户端生图链接丢失外网端口

**症状**：客户端拿到的下载图片链接不带外网端口号（例如 `https://api.example.net/v1/images/files/xxx.png`），点开打不到；而同一个链接从 web 控制台打开是好的。web 端看不出来，是因为它按页面相对路径取图，端口由浏览器补上——服务端并不知道自己错在哪。

**原因**：服务端的绝对链接由 `publicBaseURL` 推导，其中 `forwardedHost` 只要 `X-Forwarded-Host` 存在且合法就直接采用它。而一个很常见的 nginx 配置是：

```
proxy_set_header Host $http_host;          # host:52325，带外网端口
proxy_set_header X-Forwarded-Host $host;   # 只有主机名，没有端口
```

代理没有发 `X-Forwarded-Port`，于是**请求里本来带着的那个外网端口被丢掉了**，链接落到默认端口上，那里没有服务在监听。

**修复**：为"没有端口的转发主机名"补上端口——优先用 `X-Forwarded-Port`（那是代理明确声明的公网端口），没有它时**从请求自身的 `Host` 头借端口**。只借端口：主机名仍以 `X-Forwarded-Host` 为准，因为 `Host` 头有可能写的是调用方到不了的上游地址。已经带端口的转发主机名不再重复追加；默认端口（http:80 / https:443）依旧省略。

**验证**：反向验证——撤掉这段回退，就能精确复现报告里的现象（`https://365api.example.net` 而不是 `https://365api.example.net:52325`）。新增用例覆盖：借用端口、`X-Forwarded-Port` 优先于 `Host` 端口、转发主机名自带端口时不重复追加、无处可借时不乱加、两种 scheme 的默认端口省略、IPv6 形式，以及客户端实际收到的 `generatedImageURL` 端到端结果。

如果你本来就配了 `M365_PUBLIC_BASE_URL`（或管理台的公网地址），它优先级最高、不受这次修复影响，仍然是反代改写头部时最稳妥的做法。
