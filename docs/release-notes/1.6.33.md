### v1.6.33-0010 — 修复 gpt-image-2 在客户端里「无法连通」

**症状**：在客户端里添加 gpt-image-2 后，连通性检测提示「无法连通」或检测超时。真实生图功能不受影响。

**原因**：客户端的连通性检测只会发一句极短的文本（问候、`test connection`、或者它刚看到的模型名）。网关对 `gpt-image-2` 的设计是「选中即生图」——这样真实生图请求不会漏掉路由——于是这类短文本被当成生图提示词，送进了 **30–180 秒**的生图管线。客户端给检测的固定超时通常只有 30 秒，包里还没回来就被判定为不可达。

v1.6.33 早期构建处理过这类问题的一部分，但漏了三种情况：

1. **客户端回显模型名**：把显示名改成 `gpt-image-2` 就是为了让回显变成 API id，但 `gpt-image-2` 这个字符串本身没被加进识别列表，回显照样走生图——那处修复只做了一半。
2. **中文探测**：识别列表只有英文，`你好` / `测试连接` / `在吗` 一律进生图。这是个中文项目。
3. **带 `response_format` 的探测**：`gpt-image-2 不支持 response_format` 这条限制排在探测判断之前，而部分客户端给每个请求都带 `response_format`，探测会先被 400 拒掉。

**修复**：探测判断移到生图专用限制之前，任何探测都不会再变成 400 或进入生图管线；识别范围补上模型名回显、大小写与标点（`Say OK.` / `Hello!` / `你好。`）以及中英双语短语。**真实生图请求的行为完全不变**——只认列表内的探测短语，识别不出的一律照常走生图。

**验证**：新增 7 个端到端用例（模型名回显、中文问候、带标点、`response_format`、流式、含 system 轮次）与分类用例（含「一只戴帽子的猫」这类短描述必须仍走生图）。反向验证：撤掉任一处修复，对应用例立即失败。
说明：与之前几版相同，未在真实 NAS + M365 账号上跑通整条生图链路，修复依据是代码路径与客户端探测行为。

### v1.6.33 — 生图提示词与持久化下载修复

包含 v1.6.32 的全部改动，并修正图片失效提示的中文编码：

- 生图提取当前用户的实际描述，过滤客户端附加的模型名称、剩余 token 信息。
- 图片持久化保存在数据目录 `chat/generated-images/`，重启后可继续下载。保留 72 小时，最多 128 张或 512 MiB，达到容量上限时清理最旧图片。
- 保存失败不返回成功链接；失效链接显示可读中文说明。

原来已丢失的内存图片无法恢复，需要重新生成。无需卸载，覆盖升级即可。

验证：提示词提取、跨实例下载、存储失败、过期、容量清理和错误提示回归测试；此前 v1.6.32 全量测试、竞态测试与 SPK 构建均通过。本次未在用户 NAS 上执行真实生图，旧链接 404 的具体触发原因尚未确认。
