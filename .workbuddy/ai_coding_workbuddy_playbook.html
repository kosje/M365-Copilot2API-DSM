WorkBuddy × M365 网关 — AI Coding 极致体验落地手册

自动续跑 / 断点恢复 / diff 上下文的正确归属与可操作方案 · 配合网关 v1.6.0

核心边界（先读这段，避免走弯路）

M365-Copilot2API 是无状态代理：每次 HTTP 请求独立，工具由 WorkBuddy 执行、WorkBuddy 持有 Agent 循环与文件读取，网关只做 prompt 拼装 + OpenAI 协议适配。

因此：

网关做不了 自动续跑硬循环 · 计划持久化 · 读文件做 diff 网关已做到位 autonomyBoost 自主指令注入 · toolResultMode 智能压缩 · failover 放宽 · SSE 心跳 · hideReasoning

下面三项的正确实现位置是 WorkBuddy 客户端层，与网关 v1.6.0 的能力互补。

① 自动续跑（Auto Continue）

机制真相：WorkBuddy 的 agent loop 收到模型的 tool_calls 会持续执行；模型返回"完成"（无 tool_calls）则 loop 结束。"做一半就停"本质是上游模型过早判定完成，不是 WorkBuddy 没续。

✅ 网关已替你解决大半（v1.6.0 autonomyBoost）

网关在 prompt 注入「自主编码代理」指令：实现全部改动、自行跑 build/test 验证、未完成不得提前结束。效果是上游模型在回包里就把客户端循环一次性跑完，不再把"续跑"甩给你。

WorkBuddy 侧你还能做的（锦上添花）
  • 任务指令写明确：给任务时加一句「如果还有未完成的 TODO / 未生成的文件 / 未跑的测试，不要说完成，继续直到全部完成」。可固化进用户级 MEMORY.md 作为全局约定。
  • 利用自带 agent loop：你给一个完整任务，WorkBuddy 会连续执行到完成或遇真实阻塞；不要在中间手动打断。
  • 跨"以为停了"：WorkBuddy 不会自动补发"继续"，但 autonomyBoost 已大幅压低假完成率。若仍停，回一句"继续"即可（模型已带上下文）。

② 断点恢复（Plan Persistence）

❌ 网关无状态——不能持久化计划 / 进度，每次请求都是新上下文。
✅ WorkBuddy 已有机制：三层 memory 系统
项目级 MEMORY.md长期项目约定、架构事实
每日日志 YYYY-MM-DD.md当日进度、done/remaining
conversation_search跨会话检索历史讨论与决策
落地做法（就是把 plan 写进 memory）
  • 任务前：动手前先把计划写入项目 memory（.workbuddy/memory/YYYY-MM-DD.md），结构化为 done:[] / remaining:[]。
  • 任务中：每完成一项，把该项从 remaining 划到 done；遇阻塞记下卡点。
  • 下次会话：开头读 memory，即可知道"做到哪、还剩什么"，无缝续上——这就是轻量 Plan Persistence。

这正是我维护 2026-09-15.md 的模式，可直接固化为"编码任务前先写 plan 到 memory"的项目约定。

③ Diff 上下文（Diff-Driven Context）

❌ 网关读不到文件——无法做 diff，也不可能"只给变化部分"。
✅ WorkBuddy 的天然来源：git diff
  • 改完文件后 git diff 就是高质量"变了什么"上下文，比重发整文件省几个数量级 token。
  • 要让上游模型只看变化：在调 API 前把 git diff 摘要注入 messages，而非把整文件再发一遍。
  • 网关配合：v1.6.0 toolResultMode=smart 已压缩工具输出（build/test 日志）；但"diff 注入"是 WorkBuddy 调 API 前拼 messages 的事，归客户端。

接入清单（照着做）

  1. NAS 应用中心手动上传 m365-copilot2api-1.6.0.fpk（端口固定 4141）。
  2. 后台 Advanced 页 → 选 WorkBuddy 预设：hideReasoning 开 + reasoning low + toolResultMode smart + autonomyBoost 开。保存即生效。
  3. WorkBuddy 里把 M365 网关设为 OpenAI 兼容 endpoint：http://nas.lianu.com:4141/v1，model auto。
  4. 任务指令带「跑完 build/test 再结束」「还有 TODO 就继续」。
  5. 编码任务前先写 plan 到项目 memory（断点恢复）。

验证清单

压缩生效？大 build 日志是否变成几十行（toolResultMode smart）
自主跑完？上游是否自己跑 build/test 才结束（autonomyBoost）
断点恢复？新会话读 memory 能否续上 plan
diff 上下文？改文件后是否用 git diff 而非整文件重发
